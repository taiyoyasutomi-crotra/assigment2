# ファンミーティング参加受付システム(モック版)

コミュニティイベントの申込受付・先着選定・繰上・QR 受付を一気通貫で回すシステムのモックです。
顧客ヒアリングで要件を引き出すための「動く画面」であり、データモデル・状態遷移・
締切/選定/繰上ロジック・QR 照合は本実装でそのまま使える形で作ってあります。

仕様の正は [docs/mock-instructions.md](docs/mock-instructions.md)(開発指示書のスナップショット)。

## 業務フローと自動化方針(要約)

| # | 現行の運用 | 自動化 | 実装 |
|---|---|---|---|
| 1 | Google フォームを毎回作る | 自動化 | イベント登録で申込フォームが自動で生える(ログイン不要。名前・ニックネーム・メールを入力するだけ) |
| 2 | チャットで告知 | 半自動化 | 告知文を自動生成し、コピーして手動投稿(文面は編集可) |
| 3 | 定員超過を目視 | 自動化 | 締切日時で自動締切。手動締切・再募集(締切延長)ボタンもあり |
| 4 | 確定連絡を手作業 | 自動化 | 「選定を実行」で申込順(先着)に当選が確定し、全員に結果メール(当選=QR付き・待機・落選)を送信キューへ登録 |
| 5 | キャンセル時の繰上連絡 | 自動化 | 当選メール記載のURLから本人がキャンセル → キャンセル受付メール+待機1位への繰上当選メールが自動送信(運営画面からのキャンセルも同じ) |
| 6 | 紙の名簿で受付 | 自動化 | QR チケットをスマホでスキャン、無効なら入場ブロック |

## 会員はログイン不要(アンケート方式)

会員アカウント・パスワードは廃止(2026-09-05 顧客判断)。ログインするのは運営者と
受付担当だけで、会員は Google フォームと同じ感覚で申込できる:

1. 募集投稿のリンクを開く → 名前・サロンのニックネーム・メールアドレスを入力して申込
2. 申込完了時に本人専用の申込状況ページ(`/a/<token>`)が発行される(ブックマーク方式)
3. 結果は全員にメールで届く(当選は入場QRコード添付)。申込状況ページでも
   確認・QR再表示・キャンセルができる

会員確認(なりすまし・非会員対策)は選定時に、申込メールアドレスを会員名簿(CSV)と
照合して行う。名簿外は落選になり、落選メールでその旨を本人にも伝える。

### メールアドレスの打ち間違い対策

- 申込フォームでメールアドレスを2回入力(不一致は入力中に警告)
- 名簿外の申込には、管理画面で名簿の近いアドレスを「もしかして」として表示(編集距離2以内)
- ニックネーム入力により、運営者が目視で本人確認して「承認」できる
- 落選メールに「名簿と照合できなかった」旨を記載し、本人からの申告を促す

## 結果連絡メールと無料枠(送信キュー)

応募300人規模でも全員に連絡を届けるため(申込受付・当選・落選・繰上・キャンセル受付)、
無料枠に合わせた送信キューを持つ:

- 申込・選定・繰上・キャンセルはメールを `pending` として記録し、コミット後にキューが送信
- 送信チャネルは2つを併用して1日380通まで無料:
  Resend(無料枠100通/日 → 予算 `NOTIFY_DAILY_LIMIT`=90)+
  Brevo(無料枠300通/日 → 予算 `NOTIFY_BREVO_DAILY_LIMIT`=290。`BREVO_API_KEY` 設定時)
- 優先度順に送信: 申込受付・繰上・キャンセル受付(少量・緊急) → 当選(QR付き) →
  落選連絡(繰上待ち) → 落選(名簿外)
- 落選連絡(繰上待ち)は待機順位を記載せず、**繰上の可能性が低い後ろの人から**送る。
  送信前に繰り上がった場合は落選連絡を取りやめ、当選連絡だけが届く
- 予算超過分は Vercel Cron(`/api/notify/process`, 毎日)が翌日以降に自動送信。
  管理画面の「送信待ちをいま送信する」で手動でも流せる

## 技術構成

- Next.js (App Router) / TypeScript
- Postgres(Supabase 想定。ローカル Postgres でも可)
- Resend(結果連絡メール。API キー未設定時はコンソール出力にフォールバック)
- `qrcode`(QR 生成・メール添付)/ `html5-qrcode`(スマホブラウザで読取)
- ホスティング: Vercel(Cron でメール送信キューを日次処理)

通知は差し替え前提のアダプタ構造: [src/lib/notify/channel.ts](src/lib/notify/channel.ts)

## 運営者・受付担当のログイン(AUTH_MODE)

| モード | 用途 | ログイン方法 |
|---|---|---|
| `mock`(既定) | 開発・デモ | 運営者・受付をワンクリックで選択 |
| `fans_code` | 本番運用 | メールアドレス+パスワード(再設定はメールリンク) |

切替: 環境変数 `AUTH_MODE=fans_code` を設定して再デプロイ。

## セットアップ

```bash
npm install
```

`.env.example` をコピーして `.env` を作成し、値を設定する:

```bash
cp .env.example .env
```

- `DATABASE_URL`: Postgres 接続文字列(Supabase は Project Settings > Database > Connection string)
- `RESEND_API_KEY`: 未設定でも動く(メールはコンソール出力になり、通知履歴には記録される)
- `NOTIFY_DAILY_LIMIT`: 1日のメール送信予算(既定90。無料枠100通から認証メール分を残す)

スキーマ適用とシード投入:

```bash
npm run db:setup
```

```bash
npm run db:seed
```

シード内容: 運営者1名、イベント2件(定員5に申込8件 → 先着5名当選・3名待機 / 定員10に申込3件 → 全員当選)。

開発サーバー起動:

```bash
npm run dev
```

http://localhost:3000/ で申込ページ(ログイン不要)、/login で「運営 太郎」を選ぶと管理画面。

## Vercel へのデプロイ

1. このリポジトリを Vercel にインポート
2. 環境変数を設定: `DATABASE_URL`(Supabase の Transaction Pooler 推奨)、`DATABASE_SSL=true`、`AUTH_SECRET`(ランダム値)、`APP_URL`(本番 URL)、`RESEND_API_KEY`、`MAIL_FROM`
3. デプロイ後、ローカルから本番 DB に向けて `npm run db:setup && npm run db:seed`
   (既存 DB の場合は `db/migrations/` の未適用分を順に適用)

## デモシナリオ(ヒアリング当日)

1. 管理画面でイベント作成 → 申込フォームが即座に生える
2. 告知文をコピー(文面は編集可)
3. 会員として申込フォームに入力(ログイン不要)→ 申込状況ページが発行される
4. 締切 → 選定実行 → 先着順に当選が確定。結果メールが送信キューに載り、優先度順に送信
5. 当選者の申込状況ページ/メール添付でQRを確認
6. 申込状況ページから本人キャンセル → キャンセル受付メール+待機1位に繰上当選メール
7. 受付画面で QR を読む → 緑。もう一度 → 赤「入場済み」。キャンセル者の QR → 赤「キャンセル済み」
